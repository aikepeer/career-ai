# cargo-udeps audit

Per the TODO.md tooling backlog, ran `cargo +nightly udeps
--workspace --all-targets` once to identify genuinely-unused
workspace deps.

Tool: `cargo-udeps v0.1.61` on `nightly-x86_64-unknown-linux-gnu`.

## Removed (real findings)

| Crate | Dep | Kind | Notes |
|---|---|---|---|
| `careerai-llm` | `chrono` | production | Imported in workspace deps but no `chrono::*` use sites in `crates/careerai-llm/src/`. |
| `careerai-match` | `insta` | dev | Snapshot-test framework, but no `.snap` files / `insta::*` use sites in either `src/` or any `tests/*.rs` under `careerai-match/`. |
| `careerai-submit` | `careerai-render` | production | Submitters do not call render. The dep predated the M3 split that moved rendering into its own crate, then was never pruned. |

## Kept with notes (false positives)

| Crate | Dep | Why udeps flagged it | Why we keep it |
|---|---|---|---|
| `careerai-render` | `docx-rs` (dev) | udeps couldn't find a use site | Used by `tests/render_pandoc_it.rs` to assert produced DOCX content (`tmp.path().join("sample.docx")` validation). Confirmed via `grep`. |
| `careerai-submit` | `hex` (production) | Only used inside `browser_session.rs`, which is `#[cfg(feature = "browser")]`-gated. udeps was run without that feature. | Used unconditionally in the `browser` build path; gating the dep would just mean an extra `optional = true + features = [..., "dep:hex"]` round-trip. Cost is minimal. |
| `careerai-submit` | `tempfile` (dev) | Only used inside browser-gated test paths (e.g. cookie-jar tests). | Same reasoning as `hex`. |

## Re-running

This audit is a one-time pass per TODO.md. Re-run on a Cargo.toml
manifest bump or when a new dep is added:

```bash
cargo +nightly install --locked cargo-udeps
cargo +nightly udeps --workspace --all-targets
```

If new findings appear, update this file with the disposition.
